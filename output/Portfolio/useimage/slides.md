## 2. 무엇을 만들었나
- 고민을 물으면 → 철학자의 원전에서 구절을 찾고 → 그 사람의 말투로 한국어로 답한다
- 답마다 근거 위치를 함께 보여준다 (예: "마태복음 5:31~5:46")
- 원전: 니체 6권 · 공관복음 3권 · 빠알리 경장 8종 — 영어 공개 번역본 약 48만 단어
- 자살·자해 질문에는 상담전화(109) 안내, 사이비 교주 질문에는 경계
- 이미지: `s02-chat-nietzsche.png` · `s02-chat-jesus.png` · `s02-chat-buddha.png` 세 장 나란히 (`s02-philosophers.png` 는 선택)

## 3. 기술 스택과 구성
- 백엔드: Python 3.11 · FastAPI · LangChain · BGE-M3(sentence-transformers) · FAISS · SQLite · pytest
- LLM: OpenAI `gpt-5.6-luna` — 설정 한 줄로 Gemini · Groq · OpenRouter · 로컬 Ollama 로 교체
- 앱: Flutter (Android)
- 서버의 일: 질문 분류 · 검색 · 프롬프트 조립 · LLM 호출 · 답변 규칙 검사 · 사용량 한도 · 로그인 토큰 검증
- 앱은 `{persona, question}` 만 보낸다 — APK 에 넣은 키는 공개된 것과 같고, 임베딩 모델과 FAISS 는 폰에서 돌릴 수 없다

## 4. 요청 처리 흐름
- 이미지: `s04-flow.png` (슬라이드를 거의 채운다)
- 한 줄 설명 셋:
  - 질문을 먼저 여섯 갈래로 분류한다 (위기 · 사이비 · 행적 · 가르침 · 토론 · 잡담). 위기 표현은 정규식이 LLM 호출 없이 잡는다
  - 분류마다 검색 여부 · 프롬프트 형식 · 온도가 다르다
  - 답이 규칙을 어기면 무엇을 어겼는지 알려 주고 다시 쓰게 한다

## 5. 설계 결정 ① 검색
- 청크 512 토큰 — 짧은 구절(30토큰 안팎)은 같은 장 안에서 묶고, 긴 절만 문장 경계에서 나눈다
- **한국어 질문을 영어로 번역하지 않는다** — 원전이 영어라 번역이 나을 줄 알았지만 측정해 보니 가장 나빴다 (MRR 0.262 vs 0.619)
- 철학자마다 인덱스를 따로 둔다 — 니체 질문에 마태복음이 섞이는 것을 구조로 막는다
- 이미지: `s05-chart-retrieval.png`

## 6. 설계 결정 ② 판단은 코드와 분류가
- **답할 질문인지는 점수로 못 가른다** — 유사도 기준선 0.45 에서 예수의 「바람직한 삶」(0.448)이 "근거 없음"으로 떨어졌다. 「점심 메뉴」는 0.442. → LLM 분류 호출이 질문 종류를 정한다
- **위기 안내는 모델이 아니라 코드가 붙인다** — 사람이 쓴 고정 문구. 위기면 검색도 하지 않는다 (작은 모델은 "자살을 말하면 109 를 안내하라"는 조건 규칙을 지키지 못했다)
- **근거가 없으면 코드가 첫 문장을 붙인다** — "이것은 내가 책에서 다룬 문제가 아니다". 예전엔 근거 없이 지어낸 말을 니체의 말처럼 했다 (「주식 투자」에 "운명에 맞서라" — 니체의 amor fati 와 정반대)

## 7. 문제 해결 ① 자동 지표가 만점인데 답이 틀렸다
- 문제: "정답 구절의 표현이 답에 나오는 비율"로 채점했더니 두 답이 만점
- 확인: 원문과 대조하니 둘 다 논지를 뒤집고 있었다
  - 니체가 "거짓"이라 고발한 사제의 처방을 니체 자신의 조언으로 말함
  - 과부의 "가진 생활비 **전부**"를 "작은 일을 하라"로 말함
- 해결: 지표를 버리고 31문항 평가 세트를 만들어 사람이 원전과 대조 — 기준 셋: **논지 일치 · 인용 적합성 · 발화자 정합**
- 한 줄 교훈: 단어가 맞는 것과 뜻이 맞는 것은 다르다

## 8. 문제 해결 ② 음차 개념어 검색
- 문제: 「아모르파티란 무엇인가요」에 정답 구절이 26위 → 니체가 "책에서 다룬 문제가 아니다"라고 답함
- 원인: 다국어 임베딩도 음차 · 한자어(아모르파티 · 열반 · 팔복)는 영어 원어와 잘 잇지 못한다
- 해결: 개념어 사전 — **검색어에만** 원어를 덧붙인다 ("(amor fati)"). 문장 번역은 측정상 나빴으므로 개념어만
- 54개 항목을 하나씩 재서 순위가 오르는 것만 넣었다
- 이미지: `s08-chart-concepts.png`

## 9. 품질 평가
- 31문항 (철학자마다 일반 · 개념어 · 행적 · 토론 · 잡담 · 사이비 · 위기)을 실제 서버에 보내고 답을 사람이 원전과 대조
- 첫 측정: 통과 23 · 주의 4 · 실패 3 — 실패는 모두 예수 (돈 걱정을 위기로 오분류, 근거로 답하면서 "가르친 바가 아니니라"로 시작)
- 수정: 위기 기준을 "자기 생명에 관한 말"로 좁힘 · 질문 종류를 분류 호출이 정함 · 성경체 "~리요"를 말투 위반으로 잘못 잡던 검사 수정
- 수정 후: **통과 29 · 주의 2 · 실패 0**
- 이미지: `s09-chart-eval.png`

## 10. 성능 · 비용 · 테스트 · 배운 점
- 응답 평균 **5.7초**, 질문 1개 약 **$0.001** — LLM 의 추론 기능을 껐다 (켜 두면 보이지 않는 추론 토큰이 출력 요금으로 청구된다)
- 답변 규칙 검사기: 영어 혼입 · 3인칭 자칭 · 말투 · 출처 표기 · 길이. 문장을 직접 고치지 않고 다시 쓰게 한다 (고치면 근거와 어긋날 수 있어서)
- 테스트 125개 — 백엔드 72개(LLM 을 가짜로 바꿔 API 호출 없이 경로 · 검사 · 한도를 시험), 앱 53개
- 배운 점
  1. RAG 의 근거 보장은 검색된 구절까지다 — 그 밖은 모델의 기억이다
  2. 온도를 낮춰도 지어내기는 줄지 않는다 — 측정해 보니 온도 0 에서 오히려 같은 창작이 더 확실히 나왔다
  3. 프롬프트는 짧을수록 낫고, 안전은 코드로 보장한다
